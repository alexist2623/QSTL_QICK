# AXIS Notch Decimator 1M to 50k V1

Authors: Jeonghyun Park (jeonghyun.park@ubc.ca or alexist@snu.ac.kr), Farbod

VLNV: `QICK:QICK:axis_notch_decim_1m_to50k_v1:1.0`

This IP processes packed signed 16-bit I/Q data continuously. It does not have
a trigger input, so filter histories and decimation phases are never reset by
a capture event.

Signal path:

1. 113-tap Kaiser-window linear-phase FIR, decimation by 10: 1 MSPS to 100 kSPS.
2. 125-tap Kaiser-window linear-phase FIR, decimation by 2: 100 kSPS to 50 kSPS.
3. Forty SOS notch sections at 50 kSPS: 60 through 1200 Hz, with two identical
   2 Hz-bandwidth biquads at every harmonic.

The FIR design and RTL deliberately follow `axis_fir_decim_300to1_v1`:

- coefficients are generated by `scipy.signal.firwin` with Kaiser beta 10;
- the smallest odd tap count is selected after Q1.17 coefficient quantization;
- each I/Q lane uses parallel signed multipliers and a registered adder tree;
- every accepted input launches a full FIR dot product, while the decimation
  counter only qualifies every DECIM-th completed result as valid;
- accumulation is signed 48-bit;
- output uses round-half-away-from-zero and signed 16-bit saturation.

The decimation comparator is therefore absent from the multiplier and adder
data path. This changes neither the number of tap multipliers nor the external
sample sequence.

The selected quantized cascade has approximately 0.00172 dB ripple from 0 to
20 kHz and at least 84.13 dB rejection from 25 kHz through the 1 MSPS input
Nyquist band. The two FIR group delays total 676 input samples, or 676 us.

The notch engine retains Q2.30 coefficients and Q16.16 state. Its history and
coefficient MUX is registered before multiplication. Each signed 32-by-32
multiply uses four explicit, internally pipelined DSP48E2 partial products.
For each SOS operation, five 68-bit accumulation candidates are evaluated in
parallel for I and Q, and the delayed operation tag selects only the registered
result. Each 68-bit add/subtract propagates carry through a 47-bit DSP48E2 low
chunk and a 21-bit DSP48E2 high chunk in separate cycles. ZCU216 uses DSP48E2,
not DSP48E3. The serialized 40-section computation remains below the 6000
fabric clocks available between 50 kSPS outputs at 300 MHz.

The 68-bit SOS result conversion is also split at every operation boundary.
`FINAL_ABS_ST` registers the sign and magnitude, `FINAL_ROUND_ADD_ST` adds the
Q2.30 half-LSB bias, `FINAL_SHIFT_ST` removes 30 fractional coefficient bits,
`FINAL_SIGN_ST` restores the sign, and `FINAL_SAT_ST` performs signed 32-bit
saturation. Thus no finalization cycle contains the previous absolute-value,
rounding, shifting, sign restoration, and saturation chain together.

The explicit SOS arithmetic uses 40 DSP48E2 primitives in total: 20 for the
two signed 32-by-32 multiplier/reduction pipelines and 20 for the five I/Q
accumulation candidates. Vivado 2023.1 OOC synthesis at a 3.333 ns clock found
no latches and reported +0.637 ns setup slack. OOC hold timing is not sign-off
timing because the standalone clock port has no top-level `HD.CLK_SRC` site.

`design_filter.py` searches FIR tap counts, emits both coefficient formats,
checks the quantized multirate response and notch stability, and writes the
SystemVerilog package, CSV table, and `filter_design.json`.

The nominal low-frequency delay from the original 300 MSPS input through both
FIR blocks and the notch engine is about 988.89 us. The downstream DDR capture
therefore defaults to delaying storage by 50 valid 50 kSPS samples. FIR group
delay is exact; IIR notch delay remains frequency-dependent, so software can
override the DDR trigger-delay register for a measured signal band.

Validation commands (run from `src/tb`) are:

```text
vivado -mode batch -source run_xsim.tcl
vivado -mode batch -source run_dsp_pipeline_xsim.tcl
vivado -mode batch -source run_sos_ooc_synth.tcl
```

The first test checks 120 complete filter outputs bit-for-bit. The second uses
the UNISIM DSP48E2 model directly for signed multiplication and chunked 68-bit
add/subtract edge cases. The third emits utilization, DRC, timing, and latch
reports under `C:/JeonghyunPark/Workspace/Vivado_Output/axis_notch_decim_sos_ooc`.
